A capture queue for things you forward to yourself during the day — articles,
papers, Instagram reels, YouTube shorts — reviewed here and filed into your
plans by Claude Code.

The capturing half is a separate project, =info-triage=: you forward a message
to a Telegram bot, a server fetches whatever the message links to, and a sync
script pulls the result onto this machine as one folder per item. This page
covers the Emacs half — reading the queue, looking at what an item actually contains, and
throwing away what is not worth keeping.

*This whole feature is optional.* If the inbox folder does not exist on your
machine and no sync script is set, the Triage menu is not shown at all and
nothing here applies. To try it
without the pipeline, point =ps/info-triage-directory= at the small sample queue
in =samples/info-triage/info/=.

* The daily loop

1. *Productivity → Triage → Sync Now.* Opens the queue and fetches whatever
   arrived since last time, and tells the server about anything you dropped
   here. The line at the top of the queue shows how far it has got.
2. The queue is one line per item, oldest first. *Productivity → Triage → Open
   Inbox* (=C-c p I=) brings it back without syncing.
3. Read down the list. Click an item's label to see what was captured, or its
   =directory= to look through the files themselves. One click is enough.
4. Press =d= on anything not worth keeping. It goes to the Trash, and the list
   renumbers.
5. Switch to Claude Code and type =/route triage=. It sees the same list with
   the same numbers, proposes where each item belongs, and waits for you to
   approve. Naming particular items works too: "route items 3, 5 and 10".
6. Approving it files those items and deletes their folders, which the next sync
   propagates back to the server.

* The queue

Items are grouped by the day they arrived, oldest day first:

: * 2026-08-16
:
: ** 20 · Strong Model Collapse                                          :paper:
:    directory · source
: ** 21 · Ever noticed the coloured tags on the ancient trees…            :post:
:    directory · source

The number is what you quote to =/route=. It runs straight through the days and
is reassigned whenever the list is rebuilt, so quote the numbers you see now.

The label itself is the link — click it to see what was captured. Most captured
items have no title of their own, so the label comes from the item's caption,
on-screen text or transcript. The kind of item sits at the right-hand edge as a
tag.

An item you added a note to when forwarding it shows that note in italics
between the label and the links.

The =·= line beneath carries the rest: =directory= opens the item's folder, and
=source= opens the page it came from in your browser.

** Watching a sync

A sync takes a while — after the download it looks every item up in your notes
and paper library — so it runs in the background and reports in two places.

The line at the top of the queue says what it is doing and what you can do next:

: Syncing · Downloading new and edited items · 3/12   Log
: Synced 14:32 · 3 new   Sync
: Sync failed · …   Log  Retry

=Sync= and =Retry= start a sync, =Log= shows everything the sync script printed.
The list reloads by itself when the sync finishes.

When you have gone to another file meanwhile, a small marker at the bottom of
the file tree, beside the git-sync status, keeps you posted: =⇣= while a sync
is running, =⇣3= when it has finished and three new items are waiting, =⇣!=
when it failed. Hover over it for the details; click it to go to the queue (or
to the log, after a failure). The count goes away once you have looked at the
queue, and nothing is shown at all when a sync brought nothing new.

Only one sync runs at a time, and =d= waits for it to finish.

*The first time*, there is no queue yet: Open Inbox offers to sync, and the
queue opens when the sync has made it.

** Keys in the queue

The queue is read-only (it is rebuilt on every sync), so single keys act on it:

| Key           | Does                                                   |
|---------------+--------------------------------------------------------|
| =RET=, click  | follow the link at point                               |
| =n= / =p=     | next / previous item (day headings are stepped over)   |
| =d=           | drop the item at point (asks first; goes to the Trash) |
| =s=           | sync                                                   |
| =g=           | rebuild the list without syncing                       |
| =e=           | open the item's folder outside Emacs                   |
| =b= / =f=     | back / forward                                         |
| =q=           | put the queue away                                     |

* Looking inside an item

*The queue keeps its window.* The first item you open splits the frame and
takes the pane beside it; every item after that, and every link you follow
inside one, lands in that same pane, so the list stays in view. The =‹ ›=
buttons on the mode line (or =C-c <left>= / =C-c <right>=) walk back and forward
along the trail — see [[file:Files-and-navigation.org][Files & navigation]], which also covers how each kind
of file opens and how folder listings work.

To work one window at a time instead, with =‹= to get back to the list, turn
=ps/info-triage-open-beside= off.

Audio is not opened at all — the transcript beside it is the readable copy. An
item whose payload is twenty photos is one a file browser handles better: =e=
(Productivity → Triage → Open Item Externally) hands the folder to VS Code.

* Troubleshooting

*Sync fails with "No route to host"* although the same script works from a
terminal. On macOS, Emacs needs permission to reach machines on your own
network: System Settings → Privacy & Security → Local Network, switch Emacs on,
then restart Emacs. The permission is lost when Emacs is reinstalled or
rebuilt, so this can come back after an upgrade.

* Under the hood / Customize

- The Triage menu lives under Productivity and is =config.org= → /Productivity
  menu + prefix keys/. It is hidden entirely when =ps/info-triage-directory=
  does not exist and =ps/info-triage-sync-script= is not set.
- The queue, the sync commands and the drop are =lisp/ps-info-triage.el=.
  Settings — where the inbox is, which program =e= hands a folder to, whether
  items open beside the queue — are in =config.org= → /Settings → Info triage/
  (=ps/info-triage-directory=, =ps/info-triage-external-command=,
  =ps/info-triage-open-beside=). Where the sync script is
  (=ps/info-triage-sync-script=) is machine-local and goes in =local.el=.
- Opening files, back/forward and folder listings are shared with the rest of
  the config; their settings are listed in [[file:Files-and-navigation.org][Files & navigation]].
- The two generated lists, and the sync script itself, belong to the
  =agent-context-pipeline= project — see its =docs/reviewing-in-emacs.md=,
  and =docs/architecture/sync.md= for the lists themselves. Nothing in this
  configuration writes to them.
