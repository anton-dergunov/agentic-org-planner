#+OPTIONS: toc:t

[[file:Index.org][↑ Back to the documentation index]]

An optional AI assistant runs in a side window and can read and edit your Org
notes, with its proposed changes shown to you as Emacs diffs. It runs on your
Claude Pro/Max subscription.

#+CAPTION: The assistant beside a plan file, with the diff of a change it proposed
[[file:../screenshots/agent-audit.png]]

* Opening it
Press =C-c c c= to start or toggle the assistant (Productivity menu → /Claude
Code — start/toggle/). =C-c c m= opens its menu, =C-c c s= stops the session.

It opens in a side panel rather than taking over whatever you're editing —
docked to the right when your Emacs window is wider than it is tall, or to the
bottom otherwise.

Keys in the panel behave as in a terminal: one press of =Escape= closes a menu
or interrupts the assistant, and =Cmd-V= pastes into the prompt.

* What it can see
The assistant is aware of the file you are looking at and the text you have
selected in your Org files — select a few lines, click into the assistant's
window, and ask about "this". It can also open files, show you diffs, and report
Emacs diagnostics.

- *A selection is sent once, not with every message.* A follow-up question
  doesn't attach the same lines again; selecting something else does.
- *Very large selections are not pasted in.* Past =ps/claude-selection-max-lines=
  (500) or =ps/claude-selection-max-chars= (20000), only the file is reported
  and the assistant reads it itself.

With nothing selected, it is simply told which file you are in — including
right after you start a session, so the first question can say "this file".

* Reviewing proposed edits
Changes the assistant wants to make are shown as an Emacs diff (Ediff) so you
can step through them and accept or reject. Your mouse pointer stays where you
put it when a diff closes.

* Telling it how to work with your notes
The assistant reads a file named =AGENTS.md= in your Org directory (with a tiny
=CLAUDE.md= alongside that just points to it). It has two halves:

- *The general rules*, which come with this configuration: that words like
  "task", "project" and "note" mean entries in /your/ Org files — so "add a task"
  edits your plans rather than the assistant's own list — and how to edit them,
  how a good task is shaped, and how to format Org text. They reach your vault
  through the generated context file below, so an update to the configuration
  updates them everywhere.
- *What is personal to you*, written in =AGENTS.md= itself: the language you want
  things written in, where your reference notes live, files with special rules,
  how you like to work. Where the two disagree, yours wins.

Creating a vault writes a starter =AGENTS.md= with a heading for each of those,
ready to fill in. After that it is yours alone — nothing here ever writes to it
again. A folder you open as a vault keeps the =AGENTS.md= it already has; if it
has none, copy the one from the bundled sample (=samples/realistic/AGENTS.md=) and
make sure it ends with the line =@.claude/generated-context.md=.

** The generated context file
What the assistant needs from this configuration is kept up to date for you, in
a companion file that =AGENTS.md= imports: =.claude/generated-context.md= in your
Org directory.

- *The general rules* described above.
- *The conventions in force* — your TODO keywords, priorities, tags, whether
  finishing a task logs a timestamp, and where the journal lives. These come from
  =config.org=, so the assistant is told what you actually use instead of guessing
  from what it happens to read.
- *Your context tags and situations* — when you declare them (see
  [[file:Situations.org][Situations]]), two tables: what each tag promises, and which saved search each
  one feeds, so you never have to describe your tags a second time in
  =AGENTS.md=.
- *Where your capture inbox is* — when you use [[file:Info-triage.org][Info triage]], the location of its
  digest, so "route triage" needs no path.
- *An index of your plan files* — one line per file, taken from that file's
  =#+SUBTITLE:=. It lets the assistant route something to the right file without
  opening all of them. Files with no =#+SUBTITLE:= are simply left out, so writing
  one is how you describe a file's purpose.

It is rebuilt when Emacs starts, when you reload the configuration (=C-c p R=)
or your workspace settings (=C-c p w=), when you switch vaults, and a couple of
seconds after you save any plan file — so a subtitle you just edited, or a file
you just created, shows up right away. =M-x ps/ai-context-sync= rebuilds it on
demand. Since it is regenerated from scratch every time, you can safely exclude
it from version control.

Don't edit it: your changes are overwritten. Change =config.org= or the relevant
file's =#+SUBTITLE:= instead, and put rules of your own in =AGENTS.md=.

* Skills: filing and reviewing your plans
Two skills come with this configuration, and the assistant has them in every
vault:

- =/route= — files captured material where it belongs. Give it a slice of your
  inbox ("route the first ten items in Inbox.org"), text pasted into the chat, or
  the capture inbox from [[file:Info-triage.org][Info triage]] ("route triage"). For each item it decides
  whether it is worth keeping, whether it is already in your plans somewhere,
  how to phrase it as a proper task, and which file and section it goes to.
- =/audit= — reviews what is already filed: a file, a section, a selection, or
  several files. It looks for outdated or weak material, badly shaped tasks, and
  things in the wrong place. Name a check to run just that one, e.g.
  =/audit Play/Travel.org vet=.

Both report a numbered list of findings and change nothing until you answer
with the numbers to apply ("apply 1, 3–5; discuss 2"). A long list is cut off
at about fifteen findings, with a suggestion to run one check at a time.

They work best when each plan file opens with a short charter: a
=#+SUBTITLE:= line plus a few sentences under the title saying what belongs in
the file and what doesn't. The skills read it before judging anything there.

The skills live in this configuration's =skills/= folder and are linked into
your vault's =.claude/skills/= whenever a vault opens. An update to the
configuration therefore updates them too, and the assistant finds them whether
you start it from Emacs, from VS Code, or from a terminal in your vault. The
links are kept out of your vault's git history. To change a skill for one
vault, put your own folder of the same name in =.claude/skills/=: it is never
replaced. =M-x ps/skills-sync= relinks on demand and says what it did.

* Copying text from the assistant window
The live session is an interactive terminal, so a normal mouse selection there
gets cleared as the assistant keeps drawing. Two reliable ways to copy:

- Select text and press =M-w= (=Option-W= on macOS) right away to copy it.
- Press =C-c C-e= to switch the session window to a plain, read-only view where
  selection, scrolling back, and the Edit → Copy menu all work normally; press
  =C-c C-j= to return to the interactive view.

* When the assistant changes a file you are editing
If the assistant edits a file you also have unsaved changes in, your version is
never silently overwritten or discarded — see /When both sides changed/ in
[[file:Sync-and-backups.org][Sync & backups]]. Without unsaved changes, the file simply refreshes to show the
assistant's edit.

* If the assistant window looks wrong after resizing
The session window is a terminal, and resizing it makes the assistant redraw its
whole display. If it ever ends up showing blank space or missing text, resizing
it again (or scrolling) redraws it correctly. It may flicker while you drag the
divider; =ps/claude-resize-throttle-interval= trades flicker for how closely the
panel tracks the drag.

* Quitting Emacs with a session running
Emacs quits without asking you to confirm killing a running assistant session;
set =ps/claude-no-exit-prompt= to =nil= to get the confirmation back.

* Under the hood / Customize
- The panel: =lisp/ps-claude.el=; settings in =config.org= → /Settings → Claude
  Code (ps-claude.el)/ — =ps/claude-window-width=,
  =ps/claude-resize-debounce-delay=, =ps/claude-reanchor-delay=,
  =ps/claude-resize-throttle-interval=, =ps/claude-no-exit-prompt=,
  =ps/claude-selection-max-lines=, =ps/claude-selection-max-chars=,
  =ps/claude-selection-connect-delay=. Panel keys: =ps/claude-session-keys-mode-map=.
- The context file: =lisp/ps-ai-context.el=; settings in =config.org= →
  /Settings → AI context sync (ps-ai-context.el)/ — =ps/ai-context-enabled=,
  =ps/ai-context-file=, =ps/ai-context-guide-file=,
  =ps/ai-context-next-keyword=, =ps/ai-context-save-debounce=. The general
  rules themselves are =agent/guide.md=.
- The starter =AGENTS.md=: =lisp/ps-vault.el= (=ps/vault-scaffold=).
- The skills: =skills/= (one folder per skill); linked by =lisp/ps-skills.el=;
  settings in =config.org= → /Settings → Skills (ps-skills.el)/ —
  =ps/skills-install=, =ps/skills-directory=.
- The mouse pointer during diffs: =config.org= → /AI Assistant → Ediff: don't
  move the mouse pointer/; set =ediff-grab-mouse= to =t= for Emacs's default.
